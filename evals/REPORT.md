# Harness self-checks (oracle test double)

The oracle answers from gold labels, so these runs test the pipeline plumbing and the metric code, not a model. The clean run should score at or near the ceiling. The noisy run injects missed events, date shifts and altered quotes, and shows that the metrics and the grounding validator respond. **Known oracle limit:** it only emits gold events, so it never extracts the conflicting date mention in a planted date conflict. A model is expected to extract it, and the conflict rule then fires. The `missing_record` miss is a phone-call record that the deterministic follow-up rule does not cover; the issue-analyst agent (roadmap phase 3) is meant to handle it.
