# Synthetic smoke sets (dev and test)

> **All data here is synthetic.** It was generated by `medchron synth`. Every page carries a "SYNTHETIC RECORD - NOT A REAL PATIENT" banner. No real patient, provider or client is described, and every patient, clinician and facility name is invented.

| Folder | Seeds | Cases | Use |
|---|---|---|---|
| `dev/` | 1–8 | 8 | Development: prompt and rule changes are tuned **only** against dev |
| `test/` | 1003–1011 | 9 | Held out: run for reporting, never used for tuning |

Seeds 1–999 belong to dev and seeds 1000 and up to test. `medchron synth --split` refuses seeds outside the chosen split, so larger generated sets (`make synth SPLIT=test CASES=50`) cannot overlap. Both committed sets cover all six scenarios and every hazard below, and a test checks that they do.

Each case has one or two PDF **record productions** and a gold-label JSON file (`CaseGold` in [`src/medchron/synth/models.py`](../../src/medchron/synth/models.py)).

| File | Contents |
|---|---|
| `case_NNNN.pdf`, or `case_NNNN.p1.pdf` and `case_NNNN.p2.pdf` | The production(s). Page numbers in the gold run across productions. |
| `case_NNNN.gold.json` | Gold labels: a document index with page ranges, clinical events with verbatim quote and page sources, planted issues, and the ground-truth text of every page |
| `manifest.json` | Per-case summary: seed, split, scenario, counts, files, SHA-256 of each PDF, and which hazards the case contains |

Regenerate both sets with `make smoke-data`. CI checks that the committed gold labels can be reproduced exactly from their seeds. PDF bytes are deterministic for a given seed and library version.

## Scenarios

All clinical content is simplified and illustrative. Planted issues are phrased as questions for expert review, never as conclusions.

| Scenario | Course of care |
|---|---|
| `abdominal_pain_return_visit` | ED visit for abdominal pain, discharged, return with appendicitis |
| `knee_replacement_vte` | Knee replacement, change of anticoagulant, later DVT and pulmonary embolism |
| `wrist_fracture_overread` | Wrist injury, preliminary x-ray read revised by radiology |
| `ed_headache_return` | ED headache treated as migraine without imaging, return with subarachnoid hemorrhage |
| `lap_chole_bile_leak` | Laparoscopic cholecystectomy, post-operative call, bile leak treated by ERCP |
| `anticoag_interaction` | Warfarin plus a new interacting antibiotic, no INR check, gastrointestinal bleeding |

## What the benchmark tests

| Challenge | How it is planted |
|---|---|
| Messy layout | Records grouped by facility, fax headers, `Page x of y` footers, mixed date formats (`03/14/2024`, `March 14, 2024`, `14-Mar-2024`, …) |
| OCR | Pages rendered as speckled scans with no text layer: slightly tilted, **skewed 2–4°**, **fed sideways** (a landscape page) or **upside down** |
| Tables | Medication lists, medication administration records and lab panels as fixed-width tables. Event quotes are table rows |
| Copy-forward | A later note repeats an earlier dated paragraph. Gold cites it as a second source of the **original** event, so dating it to the later note is a date error |
| Misfiled page | One page of a different fictional patient's chart, filed inside a document. It should be flagged and not extracted (planted issue `misfiled_page`) |
| Incremental productions | Records up to a cutoff date arrive first, later records follow in a second production that also re-sends some earlier pages. The second run should reuse earlier work, merge restated events and add only new ones |
| De-duplication | Pages re-sent within a production and across productions (`duplicate_of` in gold) |
| Grounding | Every gold event has verbatim quotes on exact pages. Matching normalizes whitespace |
| Issue detection | `date_conflict`, `missing_record`, `record_inconsistency`, `potential_delay`, `misfiled_page` |
| Safety | `prompt_injection`: a fax cover with instructions addressed to automated systems |

## Limits

The notes are template-generated and much cleaner than real records. The scenarios are short (9–18 pages). Scanned pages use one synthetic font. Scores on this benchmark measure the system's mechanics, not its performance on real productions.
